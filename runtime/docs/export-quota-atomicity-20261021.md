# 导出额度并发与月权益

旧audit/quota服务先检查再upsert，并发可以同时通过。导出定价注册表写免费3份/月、专业30份/月，服务却按1份/天、20份/天；FULL/TEAM/MAINTENANCE不在旧映射，可能异常。读取数据库失败又按零用量处理。

导出限额现在直接引用同一定价注册表，包含六档，周期改为北京时间自然月。到期套餐按免费版，缺失或注销账户不允许消费。事务内使用PostgreSQL事务级咨询锁，按账户和额度类型串行执行读取、检查和写入；额度读取与写入失败不成功放行。非法数量拒绝执行。请求锁后才确定时间，减少跨重置边界的问题。

月用量聚合月份内全部旧日记录及新月记录，避免已有用量在切换时丢失；上一月不计。每日与每月时间边界均用UTC计算北京时间，不依赖主机时区。导出额度耗尽提示改为本月/下月。checkQuota仅为预览，真正消费必须走consumeQuota；本地直接数据库写入不受该服务锁保护。

验证：41项通过，含真实PostgreSQL12并发请求、免费月额度恰好3成功且累计3、旧日记录汇总、过期PRO降级、FULL不限量、非法数量不写入、跨年北京时间边界，以及既有完整导出与下载隔离。读取和事务失败为明确注入，其余额度测试使用真实数据库。类型检查通过。隔离测试种子均清理。证据在evidence/2026-10-21-export-quota；未执行生产迁移、真实支付或浏览器新截图。

边界与剩余工作：非导出类别仍有旧额度口径/独立计数来源，不能宣称全部会员权益一致；报告生成或文件存储失败后的退额、重试幂等仍未完成。createQuotaMiddleware现先消费再执行业务，业务失败仍需后续有幂等凭证的补偿设计；当前未找到实际调用方。超大导出内存、历史时区异常数据迁移需单独核验。四产品尚未全面完成。
