> 每条格式：现状 → 修改建议 → 验收方式。

## 1. 输出与测试的准确性

**现状**：后端已有 Oracle 数据集红线测试（R2）、V3/V30 已知值回归、fail-closed 生产守卫；但 live 供应商测试默认跳过。

> ⚠️ **2026-08-18 复核更正：「42 个技能的原始实现已丢失」这个说法混了四件不同的事。**
> 实测注册表只加载到 9 个，逐个排查后：
>
> | 原因 | 影响 | 处理 |
> |---|---|---|
> | 注册表硬编码找 `新能源智库/backend/skills`，而本仓库后端目录叫「后端」（中文） | 旧风格技能目录**从未被扫描过**，启动只留一行 `Legacy skills directory not found` | 已改为按存在性解析 |
> | `runtime/services` 比 `services/` **少三个技能**（policy_tracker / report_generation / generation_simulation） | 选错目录直接少 3 个 | 已改为取更完整的 `services/` |
> | 技能导入异常只写一行 log 就吞掉 | `report_generation.py` 因缺 asyncpg 静默消失，表现成「没有这个功能」而非「这个功能坏了」—— 而 asyncpg 就在 `requirements.txt` 里 | 新增 `get_load_errors()` 显式暴露 |
> | 真正损坏的只有 `ghi_retrieval.py`（39 行残片，第 9 行 IndentationError） | 1 个 | 已废弃，见下 |
>
> **修复后：10 个技能全部加载，零失败。**
>
> `ghi_retrieval.py` 不修复而是立墓碑，理由有三：
> ① 能力已被 RA-001（`solar_resource.py`，174 行，正常加载）覆盖，且 RA-001 走 **NASA POWER 真实数据**；
> ② 残片的 `methodology` 写死 `synthetic_reference_model` —— 合成数据冒充观测值，正是项目红线要禁的；
> ③ 全仓库无任何引用。丢失的业务逻辑无法凭空重建，硬补就得自己编造太阳辐照数值，比留个坏文件更糟。
>
> 回归测试见 `后端/tests/test_skill_registry_discovery.py`（17 条）。

**建议**：
- 建「金标准数据集」CI：每个技能 ≥3 组已知输入→已知输出（容差写明理由，如 CF ±2pp 源于 P50/P90 区间），纳入 `tests/oracle/`，门禁化。
- 数值类输出强制走「计算链可回放」：API 响应带 `calculation_trace`（公式、输入、版本号），测试断言 trace 与数值一致。
- live 供应商测试（`RUN_LIVE_AI_TESTS=1`）纳入每周定时任务而非默认跳过，失败即报警。
- 报告数值与仪表盘数值同源（同一服务函数），杜绝两处各算。

**验收**：`pytest tests/oracle` 全绿；同一项目 6 端数值一致（已有 R22 红线，扩到报告）。

## 2. 不同国家的文化差异与行为习惯

**建议**：
- 表达层本地化：日期/数字/货币/单位走 `packages/i18n` 的 locale formatter（kWh vs MWh、万元 vs $K、小数点 vs 逗号）。
- 内容层本地化：国内用户关心并网、消纳、补贴退坡、CCER；国际用户关心 ITC/PTC、interconnection queue、PPA、MACRS——同功能两套内容模板，不是互译。
- 行为差异：国内偏好「结论+怎么赚钱」前置，欧美偏好「方法论+假设+风险披露」前置；报告结构随之调整。
- 颜色/图标语义审查（红色在国内=涨/吉利，在西方=警示）。

**验收**：每 persona×市场截图走查；本地化 checklist 入 PR 模板。

## 3. 普通人看得懂

**建议**：
- 分层解释：每个 KPI 卡片三级展开——一句话结论（人话）→ 关键依据 → 技术细节（公式/术语）。
- 术语气泡：IRR/LCOE/PR 等首次出现给 15 字以内白话解释（"每投 100 块一年赚几块"）。
-  jargon 检测：前端 lint 自定义规则，正文出现未注册术语即报警。
- 所有「演示数据」标识保持现状（红线要求），但措辞统一为人话。

**验收**：非技术用户可用性测试 5 人 ≥4 人能复述核心结论。

## 4. 国内版全中文 / 国际版全英文

**现状**：已有 RAG 国际版零中文测试、web-global 违禁文案门禁、报告 global 英文渲染分支。

**建议**：
- 把「语言隔离」升级为全链路 CI：UI 字符串、邮件、推送、PDF/Word、错误消息、日志面向用户部分，国内版正则禁英文长句、国际版禁 CJK 字符（已有 `[\u4e00-\u9fff]` 检查，推广到全部出口）。
- 后端错误 message 按 `Accept-Language` 返回对应语言（红线 R20 已查状态码，需补内容语言断言）。

**验收**：`scripts/verify_language_isolation.py`（新建）入 CI。

## 5. 国际版 UI 不是国内版的翻译

**建议**：
- 信息架构分开设计：国际版首页核心卡片 = 税收抵免测算（ITC）、并网排队状态、PPA 价格对标、IRA 合规清单；国内版 = 并网进度、补贴/电价、消纳率、CCER 收益。
- 导航差异：国际版突出 "Incentives / Interconnection / PPA"，国内版突出 "并网 / 收益 / 运维"。
- 落地方式：web-global 与 web-cn 各自维护 `dashboard.config.ts`（卡片编排声明式配置），共享组件库（`packages/ui-web`），不共享页面结构。

**验收**：两版首屏卡片集合不同且各自通过 persona 走查。

## 6. 会员权益设计

**现状**：`PLAN_QUOTAS`（free 5 份报告/月、pro 50、enterprise 无限 + AI 次数）已落地并有配额测试；/billing/plans 端点已重建。

**建议**：
- 补完整权益矩阵：报告配额、AI 次数、项目数、数据源（高级气象/电价）、导出格式（PDF/Word/API）、团队协作人数、支持等级；写进 `/billing/plans` 的 data，前端据此渲染对比表（单一事实源）。
- 权益拦截统一走 `assert_*_quota`，超限返回 429 + 引导升级文案（已有 QuotaExceeded.status_code=429）。
- 补降级/到期逻辑：到期后只读、保留数据 90 天、明确提示。
- 企业版差异化：SSO、审计日志、私有部署选项写进权益而非口头承诺。

**验收**：每个权益项有一条测试（允许/拒绝边界各一）。

## 7. Skills 与 RAG 的正确性、来源与时新性

**现状**：RAGService 已重建（溯源元数据 year/last_verified_at/freshness_status、市场语言隔离）；但语料是内置小样本，技能本体大量缺失。

**建议**：
- 建「来源注册表」：每条语料带 source_url、抓取时间、核验人/脚本、下次核验截止；`freshness_status` 由截止日自动计算（已有雏形）。
- 抓取管线：优先官方源（国标全文公开系统、国家能源局、IRENA、NREL、EIA、LBNL），其次开源 GitHub（如 NREL 的 ATB 数据仓）；遵守 robots.txt 与版权，只引事实数据不搬运版权文本；存快照+哈希防篡改。
- 多方验证：同一事实 ≥2 独立来源一致才标记 `verified`，否则 `review_recommended`；冲突时全部展示并标注。
- 技能公式与公开基准对齐：LCOE/IRR 与 NREL ATB、IEA 报告数值做年度对账测试。

**验收**：RAG 命中率/来源引用率指标入库；过期语料自动降权并有 UI 提示。

## 8. 时效性

**建议**：
- 所有数据卡片显示 "as of YYYY-MM-DD"；超过阈值（政策 90 天、价格 7 天、气象 1 天）显示「待复核」徽标。
- 后台定时任务刷新语料（cron + 来源注册表驱动），失败告警。
- AI 输出涉及年份/政策时强制带数据截止日（prompt 级约束 + 输出正则校验）。

**验收**：新鲜度仪表盘；过期数据不可进入报告生成（fail-closed）。

## 9. 公式/定理/图片/视频的显示技能

**建议**：
- 公式：前端统一 KaTeX（LCOE、IRR 公式卡片，`packages/ui-web` 新增 `<Formula>` 组件），报告侧 docx 用 OMML 公式、PDF 用 reportlab 渲染为图片或矢量。
- 图表：收益曲线、敏感性龙卷风图、月度发电量柱状图走统一 `<Chart>` 技能（ECharts/Recharts 二选一全项目统一）。
- 图片/视频：电站实景、设备图走素材库（标注来源与授权）；视频摘要技能已建 fail-closed 骨架，接真实供应商后再开放。
- 所有富媒体遵循「无真实素材不显示」红线，禁止占位图冒充。

**验收**：富媒体渲染测试 + 截图走查。

## 10. UI 不堆砌：信息层级

**建议**：
- 洞察优先：每张卡片 结论（1 行）→ 证据（数字/小图）→ 行动建议（1 个按钮）→ 折叠详情。
- 首屏 ≤5 张卡；其余进「更多」；数字取整 + 趋势箭头替代长表格。
- 空状态/加载态/错误态全部设计（当前大量页面缺）。

**验收**：首屏截图评审；Lighthouse 可用性 ≥90。

## 11. 场景化覆盖全部 Skills/RAG 的验证

**建议**：
- 建「技能-场景矩阵」：每个技能至少出现在一个用户旅程测试中（资源评估→财务→诊断→报告→运维），CI 断言矩阵无空格。
- 端到端旅程：创建项目→资源评估→财务模型→生成报告→导出，每步断言 UI 与 API 数值一致。

**验收**：`tests/journeys/` 全绿 + 覆盖率报告。

## 12. 国内外合规

**现状**：红线测试覆盖 R7（注入/XSS）、R11（隔离/明文）、R14（备案号检查位）、R17（禁止假资质）、R24（依赖扫描）。

**建议**：
- 国内：生成式 AI 备案号页脚展示、深度合成标识（AI 生成内容显式水印）、数据境内存储、个人信息保护（最小收集+同意记录，已有 ConsentRecord 模型）。
- 国际：GDPR（删除权/导出权端点）、EU AI Act 透明度条款、WCAG 2.1 AA 无障碍（R21 已有雏形）、版权素材授权链。
- 合规项全部测试化，避免"文档合规、代码不合规"。

**验收**：合规 checklist → 自动化测试映射表，季度复核。

## 13 & 15. 个性化显示（每个用户不一样）

**现状**：`PersonalizationEngine` 已重建——5 人设 × 7 天 hero 卡、演示数据明示、未知用户不编造。

**建议**：
- 三层个性化：① 声明画像（注册选择角色/市场/关注技术）② 行为画像（常看页面、项目类型、导出习惯，本地计算不上传隐私）③ 订阅层（权益决定深度）。
- 个性化范围：卡片编排顺序、hero 内容、推荐下一步、日报/周报节奏；布局骨架保持品牌一致（避免"千人千面=风格失控"）。
- 冷启动：新用户 3 个问题快速画像（30 秒内），否则给市场默认人设。
- 隐私红线：行为数据本地优先，服务器只存聚合偏好。

**验收**：任意两用户同天截图不同；同一用户一周内内容演化（见 19）。

## 14. UI 美观与舒适度

**建议**：
- 设计令牌统一（已有 `packages/design-tokens`）：色板、间距 8pt、圆角、阴影、字号阶梯，两版前端强制引用。
- 暗色模式、≥4.5:1 对比度、动效 ≤300ms 且可关闭。
- 数字字体（tabular-nums）保证表格对齐；中文用系统中文字体栈，英文 Inter/系统栈。

**验收**：视觉走查 + 对比度自动检测。

## 16. 真实 UI 截图验证（Playwright）

**现状**：`scripts/ui_e2e_snapshot.mjs` 已存在；测试以 API 层为主。

**建议**：
- 用 Playwright 对 5 人设 × 7 天 × 2 市场跑真实截图（注入固定演示数据，拒绝线上随机性）。
- 截图入视觉回归（基线比对，阈值 0.1%），PR 必过。
- 覆盖「每个用户最关心的问题」视角：投资人看收益页、运维看告警页、开发看并网页。

**验收**：截图目录入库审查；视觉回归 CI 通过。

## 17. PDF/Word 报告排版

**现状**：docx/pdf 已有中文渲染器 + 新建英文渲染分支（含 "Assumptions and evidence" / "Required validation before decision"）。

**建议**：
- 中文版补齐同等结构：封面、目录（自动页码）、页眉页脚（密级+页码）、章节样式表（标题 1/2/3 统一）、图表编号与题注、附录假设登记表。
- 报告生成走「模板+数据」分离：版式定义独立文件，改排版不改代码。
- 质量门禁：导出文件自动打开解析（已有 docx 文本断言），加页数/目录/字体检查；每模板一张基线 PDF 视觉比对。
- 排版细节：货币千分位、百分比统一 1 位小数、图表 300dpi、中文字体嵌入 PDF。

**验收**：报告样式检查脚本 + 双语言导出样张评审。

## 18. Skills 的专业性与准确性（外部验证）

**建议**：
- 每个计算技能挂「参考文献」字段（标准号/论文/公开数据集），PR 要求新增技能必须带出处。
- 年度对账：与 NREL ATB（LCOE）、IEA PVPS（PR 基准）、IEC 61724（PR 定义）跑一致性脚本。
- 分类阈值（已有 GHI/WPD 分级）标注来源标准号并在 UI 悬停说明。

**验收**：技能元数据完整率 100%；对账脚本结果归档。

## 19. 5 用户 × 7 天个性化 UI 演化

**现状**：`PersonalizationEngine.get_hero_card(persona, day)` 已支持 5 人设 × 7 天，测试断言每周 ≥3 条不同 headline、演示数据明示。

**建议**：
- 拍「演化故事板」：Playwright 对 5 人设逐天截图（Day1 引导任务 → Day2-3 数据积累 → Day4-5 洞察升级 → Day6-7 周报/行动清单），拼成对比图给你评审。
- 演化逻辑：每天卡片递进（新数据→新洞察→新建议），避免简单换文案；周末给周报摘要。
- 吸引力指标化：每张卡有明确「下一步行动」；引导任务完成率埋点。

**验收**：5×7=35 张截图 + 逐人设演化说明；你过目后定稿。

## 综合建议（19 条之外）

1. **可观测性**：API 埋点（耗时/错误率/配额消耗）、前端 Web Vitals 上报，上线前接入 Sentry（配置已预留 `SENTRY_DSN`）。
2. **成本护栏**：AI 调用按用户/租户限流 + 月度成本看板，防止单一用户打爆供应商账单。
3. **特性开关**：unfinished 功能走 feature flag，主分支永远可发布。
4. **性能预算**：首屏 JS ≤200KB（当前 cn-web 首屏 ~97KB 良好，保持门禁）、API P95 <500ms（R16 红线 2s 偏宽，建议收紧到 500ms 告警线）。
5. **数据备份与灾备**：R25/R26 红线已有占位，需补真实备份脚本 + 恢复演练记录。
6. **SEO/落地页**：两版落地页（UI 专项验收_2026-07-26 截图已有）纳入构建产物，静态导出优化。
7. **先补技能本体**：42 个技能恢复/重建是当前最大缺口，建议按"资源→财务→诊断→运维"优先级分批恢复，每批配 oracle 测试。
